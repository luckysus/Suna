# 受管科研资产包与隔离导入 v1

这是 F02.2 的受管资产阶段，独立于现有元数据包 v1 和工作区备份格式1/2。可显式导出受管 CSV/JSON、原始 PNG/JPEG/TIFF 图像与已登记的 JSON 模型产物，在独立目录和独立 SQLite 中校验、保存并重复导入。**尚不向当前项目导入，不自动激活模型，不加载 pickle，不执行模型或写实测，不宣称已实现完整跨电脑复现。**

## 操作与授权

在科研项目的“活动与成果”展开“受管科研资产包与隔离导入”。主动读取清单后逐项选择资产，确认标题与资产可分享且有打包权限，再预览实际文件摘要、数量、字节和缺失依赖。没有默认勾选，未提供或位于受管范围之外的文件禁选。授权为提供者自声明，不等于许可证或科研有效性已审核。

导出会重新读取项目快照，核对预览摘要后才打开原生保存对话框，复用原覆盖确认、授权写盘和回读校验。项目、所选内容或原始文件变化均要求重新核对。配置、凭据、项目备注和未选择的资产不收集；选中的原始研究文件按原字节保留，包含它们原有的内嵌元数据。

检查包使用原生文件选择器，不接受前端绝对路径。检查通过后另行确认“仅保存到独立隔离副本”，再次选择同一包并核对精确 ZIP SHA。取消不创建副本，换包拒绝。该操作不更改当前科研项目。

## 格式

普通、非加密、非 ZIP64 的 ZIP，仅包含：

```text
manifest.json
metadata.zip
assets/<64位小写SHA256>.<受支持扩展名>
```

`metadata.zip` 是原有严格 `research-package-manifest.v1` 元数据协议，继续保留原项目/任务/资源标识、成果摘要、已知单位和血缘；不把精简记录摘要当成原成果摘要。顶层 manifest 只有以下字段，其他字段拒绝：

```json
{
  "schemaVersion": "research-managed-package.v1",
  "metadataSha256": "metadata.zip 的真实SHA256",
  "rightsStatus": "user_declared_authorized",
  "assets": [{
    "resourceId": "元数据中的资源UUID",
    "role": "dataset_source",
    "extension": "csv",
    "sha256": "原文件真实SHA256",
    "bytes": 123
  }]
}
```

此例仅说明结构，生产摘要和字节数必须实际计算。角色仅为 dataset_source、image_original、model_artifact。模型只读原登记产物，校验登记摘要和科研卡；包含配置凭据或私有路径字段的模型拒绝，不能删字段后伪称原模型哈希不变。ONNX 和超过预算的模型暂不纳入本协议。

数据集仅收集受管命名空间：objects/material-data、objects/literature-data、material-datasets、research-datasets；图像使用原 microstructure 受管原图。只从本项目真实对象和校验过的冻结来源收集依赖。工作流数据没有单独挂为项目对象时，仍保留冻结的数据ID/SHA；源文件缺失就保持缺失，不从当前项目选择猜测。

资产必须引用正确类型的元数据资源，摘要还须匹配已知冻结依赖。重复资源标识、未列明文件、错误角色、改字节、未知字段/版本、路径别名、穿越、链接、设备名称、压缩炸弹及重复 JSON 键均拒绝。外层只支持 Stored/Deflate；图片只验原始类型和字节，不以导入完成宣称组织分割/物相识别通过。

## 预算

- 最多512项候选/所选资产；元数据继续原2047条记录预算。
- ZIP 总字节及解压总量最多128MiB；逻辑资产总量也受128MiB限制，重复引用相同文件不能绕过内存预算。
- 单资产最多32MiB；JSON/模型仍遵守原严格 JSON 的8MiB、32层及数组/对象预算。
- metadata.zip 继续原64MiB总量/8MiB条目限制；最多2048项 ZIP 项，膨胀比不超过128。

超预算明确拒绝，不截断数据或规则。原始资产需按字节校验；模型适用域、预测区间、许可证和材料真实性不由这些摘要证明。

## 隔离持久化与冲突

隔离副本存入应用数据根下 `research-package-imports/<包SHA256>/`，不接受客户端指定目标路径。目录中包含原资产、metadata.zip、独立 metadata.sqlite3 和最后提交的 receipt.json。资产和收据仅用 create_new 写入；目录/文件边界沿用原路径授权与句柄校验。独立 SQLite 新建于本次专用目录，使用新UUID映射与原始引用记录，血缘指向新映射，不使用用户主库连接。

完成后关闭再只读重开 SQLite，并回读核对资产、原记录摘要和ID映射。同一包重复导入返回原映射；已有目录或摘要不一致、被改字节、未完成的副本均拒绝覆盖。可控失败回滚本次新建目录，其他副本、原始文件、主库、配置和原模型均不改写。崩溃中断后遗留的不完整副本明确报错，自动修复/清理留给恢复阶段，不能假报重试成功。

返回状态明确区分 `assetsRestoredToIsolation=true`、`assetsRestoredToLiveWorkspace=false`、`writesToLiveWorkspace=false`、`readyForComputation=false`。这些隔离副本尚未纳入原工作区备份范围。导入完整项目、恢复标注/完整成果正文、外部授权文件重定位、领域包冲突处理与两台真实设备复现仍是后续范围。个人 Windows 原生弹窗、权限拒绝/磁盘不足和中断恢复仍待实机验收。

## 已保存副本的只读查看

新版本原生隔离导入会在同一受控回滚目录内保存**原ZIP字节** `package.zip`，在最后完成收据中记录 `originalArchiveStored=true`。不会重建ZIP后冒用原包SHA；Stored/Deflate两种合法包均按原字节校验。额外保留原包需要相应磁盘空间，容量不足和原生中断仍须Windows验收。

在“查看已保存的隔离副本”主动读取列表。列表每页25项，仅显示“已保存，尚未重新校验”“旧副本需要原包校验”或“不完整/不可读”，不把读取收据当作验证成功。只扫描应用自身隔离目录的直接条目，最多10000项；超预算明确拒绝，绝不递归搜索用户硬盘。

打开一个副本会重新读取并校验原ZIP SHA、完整协议、独立SQLite摘要及对象、新ID映射、全部资产字节，再按25条分页显示元数据。原ID、隔离ID和元数据记录SHA保留；原冻结成果SHA单独显示，不把精简元数据摘要冒充成果摘要。此处仍只有元数据引用，没有补造原成果/标注正文，也没有恢复为可计算项目。

旧版收据未记录原ZIP的副本仍通过重新选择原包做原有完整校验；列表明确要求原包。查询/打开/重复导入不会自动修改其收据、回填ZIP或覆盖旧目录。改字节、损坏数据库、映射冲突或链接目录必须拒绝，不就地修复证据。副本仍未进入工作区备份。

不同资源可以引用同一个 `assets/<sha>.<ext>`：磁盘仅写一份物理文件，SQLite保留每个逻辑资源及独立新ID；逻辑资产总量预算仍逐项计数。
