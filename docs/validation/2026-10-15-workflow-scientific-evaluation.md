## 实际改动

- 两个独立性能模型分别配置科研评估，完整选项通过原桌面桥写入不可变模板版本，再进入原只读预览、显式确认和训练任务。修改任一选项使旧预览失效；两模型的设置不会互相覆盖。
- 修复原 Rust 传参遗漏：只设置 `learningCurve` 或 `searchTrials` 时，原条件没有生成 `evaluation`。实际新增回归在修复前失败；现在识别这些选项，并在创建任务前按现有Worker限制拒绝未开启CV的搜索/学习曲线、非法比例/折数/类型、超过12次搜索或不支持搜索的算法。合法设置保持真实值，不伪造结果。
- 工作流预览按过滤缺失目标后的实际有效行数检查高级评估的10样本下限；独立测试/校准与拟合/调参分离仍由原Worker执行。少量校准样本不能宣称95%覆盖，分组/时间条件仍显示可交换性限制。
- 两个目标及每个模型自己的划分辅助列都不能作为该模型的特征。切换划分策略会清理不用的辅助列，防止旧列残留导致校验冲突。
- 旧模板不自动开启测试、校准或CV；独立关闭的搜索/学习曲线标记保持原载荷语义。未记录种子的旧模板显示原Rust实际默认0；新模板和预测页明确设置的42及用户自定义值保留。旧模板正文/哈希、模型卡协议及冻结产物不重写；旧版可保存但Worker不支持的参数仍能查看，执行预览会拦截。
- CV明细和学习曲线保存在原不可变训练产物。模型卡复用实际记录的划分计数、种子、独立测试指标/覆盖率和数据SHA，不改变历史卡摘要。
- 修正验收工具说明中的两个命令路径，明确从仓库根目录使用 `tools/windows-acceptance/scripts/`；原脚本和权限边界未变。

- 先补回归：旧逻辑单独设置学习曲线时 `evaluation` 为Null；第二次回归证明无CV的标志被当作普通训练请求静默忽略。修复后拒绝无效组合，带CV的合法请求完整传入Worker；关闭标记与旧请求逐值一致。
- 真实120行合成CSV → Rust只读预览/模板存储 → 原Scheduler → 两次独立Python训练 → 联合优化 → 待确认计划 → SQLite重开/模型卡验哈希。模型1随机划分/种子17/CV3；模型2时间划分/种子31/CV2/一次搜索；均实际生成3个学习曲线点。
- 每个模型独立测试24行、校准24行；四分区无交集，CV不含测试/校准行；卡片保留实测测试覆盖率及 `exchangeability_verified=false`。未激活任何模型，未写实验测量。
