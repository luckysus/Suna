# 工作流固定变量、线性约束与候选单位

基线为 main `7c02342608b56e998f226087aa3e58793c04338b`；其 [Windows Run 38685354955](https://github.com/luckysus/Suna/actions/runs/38685354955) 已逐项核对全部31步成功，包括 Complete job。审计发现：工作流模板、SQLite 与执行器已支持 constraints/fixedValue，但模板编辑器没有入口；此外，没有专业规则快照时，优化候选生成实验计划会丢失单位。

本里程碑复用原模板仓库、Tauri 命令、Scheduler、联合优化 Worker 和专业约束引擎，没有新增调度系统、依赖、迁移、系统权限或 Provider 配置。

## 实际变化

- 专业优化页和科研工作流共用线性约束编辑器，配置等式、不小于、负系数上限、阈值和容差。模板可保存固定值，清空后恢复搜索；新类型与原联合优化接口一致。
- 配置变动沿原流程使预览、确认和 nonce 失效，保存新修订后才可重新预览和启动；历史修订保持不变。移除仍被约束引用的变量时明确提示，不静默丢弃约束系数。
- 只读业务预检把手工约束和已审核项目硬规则合并，使用原材料线性可行性算法检查边界与固定值。等式转换为含容差的两条不等式，不小于按相同容差约定处理；Worker 仍对实际候选复核，不以数学预检代替模型适用域或物理验收。
- 执行预检合计最多64条约束、最多24个变量，并保留原复杂度和浮点溢出限制，超限明确拒绝。旧版较大的模板仍可读取，不截断规则或改写旧版本；不含手工约束的既有流程继续原有校验。
- 联合优化任务仅增加优化变量名称/单位的小型冻结 schema，沿原成果投影保存。实验计划从该冻结 schema 读取单位，允许 fraction/K 与训练的 wt%/degC 不同；历史成果沿原专业规则快照回退，均未记录时保持未知，不从当前数据集猜测。没有修改历史成果、原始文件或哈希。
- 预检稳定错误码显示对应的中文纠正提示，其他错误继续原脱敏通用提示；不把后端路径、凭据或未知异常正文送到页面。

新增真实 Scheduler/Worker 测试：保存新模板修订，实际训练两个独立模型，联合 NSGA-II 使用 fraction 固定成分与 K 温度约束；逐候选复核固定值、等式残差和负系数上限。生成 proposed 实验计划后关闭任务和 SQLite，再重开核对模板、冻结成果 SHA、计划数值/单位。旧修订未改，模型不自动激活，实测记录数保持0。另从不含单位元数据的合成历史成果生成计划，单位保持未知。

其他回归覆盖：固定值越界、未知变量、固定值与手工约束冲突、手工约束与项目规则合并冲突、容差附近的常数等式、约束/变量预算和溢出；失败时创建0个后台任务。前端通过实际编辑、保存接口、再加载、删除引用、重新预览和确认的交互验证状态，不把服务夹具称为原生 Tauri 验收。
