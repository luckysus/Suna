# 显微图像输入首阶段：TIFF 与 16 位灰度

先审计 main `c6eabf8a7726ef881ff1852e40122fdd36e61b19`：已有图像仓库、不可变原图/标注、原生授权入口、Scheduler/Worker、阈值统计、人工审核、报告和备份；`image` 已启用 TIFF 解码，但业务入口及 Worker 仍限制 8 位 PNG/JPEG。本次扩展原流程，不另建页面、数据库或调度系统，不新增依赖或更改权限。

## 实际实现

- 原始字节保持不变；解码在原有 32MiB、1600万像素、边长8192/128MiB 解码分配预算内。TIFF 在解码前检查单页经典 IFD、布局、光度和方向；拒绝多页、子图、BigTIFF、特殊方向等不明确输入。
- 支持单页普通 TIFF 8 位灰度/RGB 与无符号 16 位灰度、PNG 16 位灰度。16 位须明确配置完整量程或整数窗口，不按各图自动归一化。Rust 预览和 Worker 使用同一版本整数映射，源文件不做灰度覆盖。
- 原图元数据和成果、实际任务载荷、逐图统计均记录同一输入协议；本地登记校验源 SHA/输入协议/宽高。没有协议的历史图像保留 v1 路径，不更新旧元数据或冻结摘要。标尺仍来自用户两点/真实长度，倍率不生成物理尺寸；原始栅格坐标不做 EXIF 变换，TIFF 非默认方向拒绝，PNG/JPEG 保持既有原始栅格规则。
- 前端可配置并向真实桌面桥提交参数，显示已持久化位深/映射/方向/色彩处理范围。错误、取消、旧数据和批量单图失败沿用现有流程。
- `fixtures/microstructure` 提供自行生成、CC0 的真实 TIFF/PNG 字节、明确源像素和独立期望、源 SHA、大小端/负例。不是第三方科研图像或材料相真值。像素测试还发现原预览会放大小图，已改为仅缩小并检查完整像素一致。
- Actions 观察脚本兼容新 React 嵌入状态及旧页面；验证仓库/提交/运行地址，未知结论或缺少任一作业完成步骤均不报成功。没有调整 CI、安全扫描和权限。
