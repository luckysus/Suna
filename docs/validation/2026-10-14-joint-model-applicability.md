## 已有实现、差距和改动

复用已有独立模型 NSGA-II、每目标方向、仿射成本函数、材料规则引擎、Scheduler/任务事件和成果快照。审计发现原联合评估按名称排列输入，但未转换各模型训练单位，也未冻结每个候选的逐模型训练支持域风险。

Rust 从已完成本地训练任务读取模型，使用原材料单位引擎编译输入和目标输出转换，覆盖调用方提供的转换参数。不同特征顺序按各模型冻结 schema 处理；无单位的旧 API 仍按模型输入单位解释，显式单位而模型单位未知时拒绝猜测。硬度尺度不互换，非有限值和转换溢出拒绝提交。

一次候选评估同时调用各模型；同一转换后的数值用于预测和支持域评估，原模型产物保持。风险冻结产物 ID、完整模型 SHA256、支持域 SHA256、数据 SHA256、目标/候选序号、触发特征和阈值、校准条件。现有 Worker 产物 ID 为 24 位，完整 SHA256 为单独 64 位字段，两者均绑定来源，不改写旧 ID 或模型哈希。

默认 `annotate_all` 保留原可行候选。用户明确选择 `within_domain_only` 后，仅筛选本次返回的 Pareto 前沿；未知支持域不视为通过。筛选为空时任务完成并报告 `insufficient_domain_candidates`、前后数量和排除数；专业约束不变，不生成联合置信度或材料物理可行性结论。旧单模型请求继续使用原非空结果校验；允许空结果仅限已核对策略/来源/计数的联合筛选。

结果经 Rust 校验模型/支持域/数据/候选绑定，使用专用投影保存到现有任务、科研成果和 manifest。没有新任务系统、迁移、备份格式、权限例外或新的训练器。风险错误只显示固定代码，不输出模型 Blob、输入行或路径。整份联合结果超过 2 MiB 时明确失败，不静默截断风险证据。

现有优化页面通过 desktop bridge 提交策略，呈现逐模型风险、阈值及单位、完整来源哈希和校准限制；历史未记录风险的任务显示未知。空筛选结果无可加入实验计划的候选。JSON 原生导出沿用既有授权文件服务。

## 实际验证

所有数据为合成夹具。云端使用 Linux、Rust 1.99、Node 24.19 和锁定 Python 环境。

实际 Scheduler → stdio Worker → SQLite 测试训练一个线性模型和一个 Random Forest。第二份合成冻结请求用现有材料引擎把同一物理来源表达为 K/fraction，并记录转换；不修改原 CSV 或模型。该夹具验证联合后端能处理不同模型单位，不宣称当前训练页面提供跨数据集单位训练流程。

检查正常域内、可行域外、显式筛选空结果、每个模型证据、项目 manifest、原 CSV SHA、模型产物与数据库重开。前端交互测试调用实际页面/bridge 入口，检查默认标记、明确筛选、完成空结果和计划入口。
