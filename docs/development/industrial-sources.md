# M4.5 工业来源与专业软件文件交换

沿用 SQLite 科研项目、`steel_datasets`、原数据库连接/系统凭据及 `database_query` 调度器；迁移0043只追加不可变来源快照和只读模板。不更换驱动或写回生产库。

数据实验室 → 专业数据源，选择项目后可导入 CSV/XLSX/对象数组 JSON。文件复制进受管 `objects/material-data`，保存原文件SHA256、软件/版本、授权声明、批次、显式输入条件与输出单位；创建新草稿，在已有字段映射界面核对后激活、训练。文件中的软件计算值标记 `external_simulation`，不能当作实测。重导相同哈希不会覆盖数据集；失败清理新文件并回滚成果、血缘及审计。

适配器协议包含能力、模式、schema版本、许可证和确认要求。JMatPro/Thermo-Calc仅接受用户依法取得的文件，没有臆造商业API、调用许可证或控制设备。自建软件的合成文件可以离线验证完整流程。

生产连接先在已有连接设置中配置、测试。当前驱动支持SQL用户名认证，口令仍走系统凭据管理；Windows集成认证未实现。保存数据库、表/视图和列白名单、批次列、行数限额，生成不可变模板。批次通过`@P1`参数绑定，不能拼接SQL；调度执行前重新核对模板与工作区。跨网查询由用户显式点击提交，可沿用取消、超时和任务恢复。

结果流最多256列、一万行、32MiB；预览只向前端返回20行，不返回缓存路径、用户名或密码。精确保留SQL decimal、整数、浮点及采样时间；不支持的非空二进制/XML列明确报错，不冒充空值。结果导入后是新的草稿CSV，来源记录连接引用、模板与参数哈希、查询时间、批次、列映射和截断状态；企业原始行不进入manifest。达到限额需用户按批次拆分，尚未实现跨批次自动分页合并。

验证：仓储测试覆盖参数注入、工作区隔离、模板不可变、文件副本、模拟来源、查询缓存导入、新版本及不泄露凭据。`industrial_file_loop`启动真实Rust Scheduler和Python Worker，完成合成文件→激活映射→线性模型→项目血缘→数据库重开，无需商业软件。

**验收边界：** 查询缓存测试使用明确标注的夹具，不能代替实际SQL Server连接测试。本环境没有隔离SQL Server和系统凭据，参数化读取与训练的完整数据库实机验收仍待执行；Windows Credential Manager、集成认证、原生对话框也未通过。本文件不宣称M4.5的所有外部验收已完成。

隔离数据库后续验证：创建只读账号及测试视图；含decimal/日期/空值/中文批次；测试含引号的批次仅绑定参数；读取→新快照→映射→训练；另测超时、取消、禁用连接、行/字节限额、重启恢复，确认整个流程没有执行写SQL。不要使用生产库。
