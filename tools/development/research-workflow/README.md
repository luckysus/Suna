# 科研工作流隔离验证

此目录不是 Suna 已安装的功能。它引用最新 main 的真实 Suna 库、数据集、训练、科研模型登记、联合优化、候选计划 API，以及已有 Scheduler、任务状态与 SQLite。主仓库仍保持当前已推送提交，未修改用户配置、凭据或旧成果。

当前 Linux 实际验证 **26 项通过**：7 项模板 schema、4 项只读业务干跑、6 项真实 Scheduler/Worker/SQLite 运行回归、3 项版本化模板存储、1 项专业规则修订、3 项生命周期/确认守卫和 2 项安全状态投影。测试使用合成 CSV；受控长任务是故障注入，不是真实性能验收。两个独立预测模型、联合优化和实验计划的基础闭环使用真实锁定 Worker。

启动必须绑定已保存的模板版本、内容 SHA、项目、源数据 SHA、材料规则 SHA 和确认预览 SHA。来源与父子任务关联使用原有 research_artifacts/research_run_sources，不新增第二套任务状态或模型注册表。已有保存点支持节点创建与检查点原子提交；取消保留原任务仓库的 CAS 事务，维护钩子恢复中断的级联取消。

已验证原版本在新版本保存后仍保持不变，切换当前项目不会改变既有来源，登记后检查点缺失可恢复而不重复模型，失败节点可安全手工重试，单工作线程占用时维护函数可触发取消，篡改检查点不能取消同项目的其他任务，结果来源 DAG 和哈希在数据库重新打开后保持。

运行命令：激活 Rust 环境后，`CARGO_TARGET_DIR=../../../src-tauri/target cargo test --offline --jobs 1 -- --test-threads=1`。测试读取 SUNA_REPO_ROOT（默认本目录向上三级的 Suna 仓库）和已有 SUNA_COMPUTE_WORKER_PYTHON；按 Windows/Linux 选择锁定 venv 路径。已去除原型专用 SQLite backup feature，清理临时目录前关闭数据库。**这里只实际运行了 Linux，尚未验证 Windows。**

仍待正式接入：版本表迁移、Tauri/Agent 权限入口、实际 Worker 依赖诊断、桌面编辑/只读预览/人工确认、已有 Inspector 与事件订阅，以及把维护函数接入现有 Scheduler。原型维护函数由测试明确调用，不是已安装的后台服务。atomic_mut/scoped_mut 为现有保存点/连接级项目范围的隔离适配；接入时扩展原 helper。

`project_manifest_fixture` 可用真实仓库导出 1100 个合成成果、1100 个项目链接与 4 条血缘边，供归档原型验证分页、去重和临时导入。输出采用独占创建，所有私密样例都是合成哨兵。

生产接入前还必须关闭模型登记的取消/超时竞态：在原模型登记事务内部校验父任务运行许可，并让工作流创建的首版本保持非激活；现有独立注册 API 的默认激活行为仅发生在这些隔离合成夹具中。尚未通过 Windows 验证。
